# TAZA 041

نظام ويب لإدارة مطعم TAZA 041، مكوّن من Laravel API وواجهتين ثابتتين: موقع الزبون ولوحة الموظفين.

## المتطلبات

- PHP 8.2 أو أحدث
- إضافة PHP `intl`
- Composer
- SQLite لبيئة التطوير المحلية
- MySQL/MariaDB عند تجهيز بيئة النشر

لا يحتاج المشروع إلى Node.js؛ ملفات CSS وJavaScript المستخدمة موجودة جاهزة داخل `public`.

## الإعداد

```bat
composer install
copy .env.example .env
if not exist database\database.sqlite type nul > database\database.sqlite
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

الإعداد الافتراضي في `.env.example` يستخدم SQLite، ولا يحتاج إلى خادم قاعدة بيانات
منفصل. للتحقق من تفعيل `intl` على Windows استخدم:

```bat
php -r "echo extension_loaded('intl') ? 'intl loaded' : 'intl missing';"
```

عند استخدام XAMPP يجب أن يحتوي `php.ini` على `extension=intl` دون فاصلة منقوطة
في بدايته، ثم يعاد تشغيل أي خادم PHP كان مفتوحًا قبل التعديل.

عند تجهيز خادم يستخدم MySQL أو MariaDB، غيّر إعدادات البيئة هناك فقط:

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=taza041
DB_USERNAME=root
DB_PASSWORD=
```

عند تشغيل `migrate --seed` في بيئة `production` يجب أيضًا ضبط
`INITIAL_ADMIN_PASSWORD` بقيمة فريدة من 12 محرفًا على الأقل. في الإنتاج يُنشأ
حساب المدير الأول فقط، ولا تُنشأ حسابات العرض الأكاديمية. إذا كانت حسابات العرض
موجودة مسبقًا وما زالت تستخدم كلمات المرور الافتراضية، سيغيّر الـseeder كلمة مرور
المدير ويعطّل بقية تلك الحسابات تلقائيًا.

بعد التشغيل:

- موقع الزبون: `http://localhost:8000/`
- لوحة الموظفين: `http://localhost:8000/dashboard`
- الـ API: `http://localhost:8000/api`
- فحص الجاهزية: `http://localhost:8000/api/health`

## التشغيل السريع على Windows

توجد ملفات التشغيل التالية في جذر المشروع، وجميعها تعمل مهما تغيّر مكان مجلد المشروع:

- `start-backend.bat`: يشغّل Laravel على المنفذ `8000`؛ اترك نافذته مفتوحة.
- `start-frontend.bat`: يشغّل خادم الفرونت المستقل على المنفذ `5500`؛ اترك نافذته مفتوحة.
- `open-index.bat`: يشغّل نافذتي الباك والفرونت مصغرتين ثم يفتح صفحة الموقع الرئيسية.
- `open-dashboard.bat`: يشغّل نافذتي الباك والفرونت مصغرتين ثم يفتح لوحة الموظفين.

الموقع ولوحة الموظفين يعملان من خادم الفرونت على `http://127.0.0.1:5500`،
ويجلبان البيانات من Laravel API على `http://127.0.0.1:8000/api`.

## تطبيق Flutter الرسمي

تطبيق الهاتف الرسمي محفوظ كمشروع مستقل بجانب مشروع Laravel، وليس داخله:

```text
../taza041_flutter_customer_mobile
```

هذه هي النسخة المرجعية الوحيدة لتعديلات الهاتف مستقبلاً. لا تُنشأ نسخة منها داخل
هذا المستودع أو داخل `public`؛ فـ`public` مخصص فقط لملفات موقع الزبون ولوحة الموظفين.
يستخدم تطبيق الهاتف واجهات Laravel نفسها على `/api`، وتوجد تعليمات تشغيله واختباره
داخل ملف `README.md` الخاص بمشروع Flutter.

## مسارات التوصيل الحية

- يحسب Laravel طريق السيارات الفعلي عبر OSRM ويعيد المسافة والمدة و`GeoJSON Polyline` إلى الويب وFlutter.
- تُحسب الأجرة من مسافة الطريق المخزنة وفق إعداد لوحة الإدارة (`5 ل.س` لكل `100م` افتراضيًا)، ويُطبق حد المسافة من الإعداد نفسه على الـQuote وإنشاء الطلب.
- يُحفظ المسار مع طلب التوصيل، لذلك يرى الزبون والسائق ومدير التوصيل الخط نفسه. إذا تعذر مزود الطرق يستخدم النظام تقدير Haversine احتياطيًا ويعلّمه صراحةً كمسار احتياطي.
- يمكن تبديل مزود OSRM إلى خادم مستضاف ذاتيًا من دون تعديل الكود:

```dotenv
DELIVERY_ROUTING_ENABLED=true
DELIVERY_ROUTING_BASE_URL=https://router.project-osrm.org
DELIVERY_ROUTING_PROFILE=driving
```

خادم OSRM العام مناسب للتطوير والتقييم. في الإنتاج يفضّل خادم OSRM مخصص أو مزود ذو اتفاقية خدمة مناسبة، مع إبقاء الرابط عبر HTTPS.

## حسابات التقييم

ينشئ Seeder حساباً لكل دور. حساب المدير العام هو `admin` وكلمة مروره الابتدائية `Admin@041`. بقية الحسابات هي `order_mgr`, `delivery_mgr`, `inventory_mgr`, `finance_mgr`, `comm_mgr`, و`driver`، وكلمة مرورها الابتدائية `Staff@041`. يجب تغيير كلمات المرور خارج بيئة التقييم.

> لا تشغّل `php artisan migrate --seed` في الإنتاج؛ بيانات الـ Seeder مخصصة للتطوير والتقييم فقط.

## حدود النسخة الأكاديمية

المشروع مجهز للتشغيل والعرض المحلي الأكاديمي. يعمل الدفع النقدي ونقاط الولاء، أما
سيريتل كاش وشام كاش فمعطلتان عمدًا لأنهما تتطلبان تكاملًا تجاريًا خارجيًا. يستخدم
التوجيه مزود OSRM العام مع مسار احتياطي عند تعذر الاتصال، ولا يحتاج العرض المحلي
إلى نطاق عام أو HTTPS أو بريد SMTP أو مفاتيح توقيع تجارية.

## النشر العام الاختياري

هذا القسم مرجعي فقط ولا يُعد عملًا متبقيًا من النسخة الأكاديمية. عند تحويل المشروع
مستقبلًا إلى خدمة عامة، استخدم `.env.production.example` كقائمة حقول مرجعية، ثم
خزّن ملف `.env` الحقيقي على الخادم فقط ولا تضفه إلى Git:

- استخدم HTTPS واضبط `APP_URL` و`CORS_ALLOWED_ORIGINS` و`SANCTUM_STATEFUL_DOMAINS` على النطاقات الفعلية فقط.
- أبقِ `APP_ENV=production` و`APP_DEBUG=false`، وأنشئ `APP_KEY` جديدًا على الخادم.
- خزّن كلمات مرور قاعدة البيانات والبريد وأي مفاتيح خارج المصدر، ودوّر أي سر يُشتبه بتسربه.
- أنشئ حسابات الموظفين بكلمات مرور فريدة، ولا تستخدم حسابات التقييم أو كلمات مرور الـ Seeder.
- لا تفعّل أي دفع إلكتروني قبل استبدال المحاكاة ببوابة المزود الحقيقية؛ سيريتل وشام مرفوضتان من API حاليًا، بينما يعمل النقد ونقاط الولاء فقط.
- شغّل `php artisan config:cache` و`php artisan route:cache` بعد ضبط البيئة، ثم اختبر `/api/health`.
- اجعل مجلدات `storage` و`bootstrap/cache` قابلة للكتابة من مستخدم الخدمة فقط قدر الإمكان.

قالب الإنتاج لا يحتوي أسرارًا صالحة للاستخدام، ولا يجوز نسخه إلى `.env` دون تعبئة
القيم الخاصة بالخادم. عند تعطيل التصحيح لا يعيد الـ API تفاصيل الاستثناءات للعميل.

## الفحص

```bash
php artisan test
php vendor/bin/pint --test
composer check
```

الأمر `composer check` يشغّل تنسيق PHP والاختبارات معًا، وهو بوابة الجودة الموحّدة.
الأوامر المباشرة تعمل بأمان على Windows حتى عندما يحتوي مسار المشروع على الرمز
`&`. يجب تشغيل Pint عبر `php vendor/bin/pint` لا عبر ملف `pint.bat` في هذه الحالة.

## حالة الإصدار

تفاصيل المصدرين المعتمدين، نتائج بوابات الجودة الحالية، وحدود النسخة موثقة في
[STABLE_RELEASE.md](STABLE_RELEASE.md).

الواجهة تحاول الاتصال بنفس أصل الموقع تلقائياً. عند تشغيلها من خادم تطوير منفصل
على منفذ `5500` أو `5173` أو `3000` أو `8080` يمكن تحديد `window.TAZA_API_BASE`
أو قيمة `taza_api_base` في Local Storage. عند التشغيل من Laravel أو في الإنتاج تُهمل
قيمة Local Storage القديمة ويُستخدم أصل الصفحة نفسه لحماية بيانات الدخول من التوجيه الخاطئ.
